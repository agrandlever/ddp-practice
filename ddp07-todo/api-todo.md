## 1. 本書の範囲

本書は[要件定義書1.1](requirements-todo.md)を上位の基準とし、[機能仕様書1.2](functional-spec-todo.md)の6機能・4画面を、指定された8つのエンドポイントで実現するための設計を定義する。

APIはプログラム間の通信窓口、エンドポイントはリクエスト（処理の要求）を受け付けるメソッドとURLの組み合わせを指す。本書ではブラウザからの画面表示・フォーム送信を扱う。応答はThymeleafで生成するHTML画面、またはリダイレクト（ブラウザを別のURLへ移動させる応答）とする。

Controllerはリクエストを受け付けて処理と表示先を決める役割を指す。本書のメソッド名の `()` は名称の表記であり、Javaの引数定義を確定するものではない。

技術構成はJava 21、Spring Boot 3.4系、Thymeleaf、Spring Data JPA、H2 Database（インメモリ）、Bootstrap 5、Gradleとする。対応ブラウザはWindows版Chrome最新版、文字コードはUTF-8とする。データはアプリ起動中のみ保持し、終了後は失われる。

## 2. 共通仕様

### 2.1 リクエストと応答

- GETは画面表示、POSTは登録・更新・削除・完了切替に使用する。GETではデータを変更しない。
- 登録・更新はHTMLフォームから `application/x-www-form-urlencoded`（項目名と値を組み合わせるフォーム形式）で送信する。文字コードはUTF-8とする。
- `{id}` はURL内の対象タスクIDを表す。対象の指定はURLで行い、登録時のIDはサーバー側で付与する。
- 登録・更新で入力する項目は `title` と `description`。完了状態は登録時に未完了、更新時には維持する。
- 削除・完了切替はURLのIDだけで対象を特定する。タイトル・説明や変更先の状態をフォーム項目として要求しない。
- POSTの成功後は指定のURLへリダイレクトし、GETで結果画面を表示する。結果画面の再読み込みで変更要求を再送信しないようにする。
- 入力エラー時はリダイレクトせず同じ入力フォームを再表示し、入力内容と項目ごとの日本語エラーを保持する。
- 保存成功後にのみ成功メッセージを表示する。失敗時は各エンドポイントの規定に従い、既存の画面内で案内する。
- メッセージID・文言は機能仕様書8章に従う。リダイレクト時は移動先に結果メッセージを引き継いで表示する。

### 2.2 入力項目

バリデーションは入力値の検証を指す。登録・更新で共通のルールをサーバー側でも適用する。独自の文字数計算は追加しない。

| 項目 | 送信箇所 | 必須 | ルール | 入力エラー |
| --- | --- | --- | --- | --- |
| title | 登録・更新フォーム | 必須 | 前後の空白を除去した後、1～100文字。未入力・空白のみは不可 | MSG-006: タイトルを入力してください。／MSG-007: タイトルは100文字以内で入力してください。 |
| description | 登録・更新フォーム | 任意 | 500文字以内。未入力は説明なしとして扱う | MSG-008: 説明は500文字以内で入力してください。 |
| id | 詳細・編集・更新・削除・完了切替のURL | 必須 | 対象タスクのID。対象が存在するかを取得時に確認する | 対象なしの場合はMSG-011。各エンドポイントの規定に従う |

IDの形式不正など、既存設計書に定義のない要求形式への独自のエラー処理は本書では追加しない。「入力エラー」は主にtitle・descriptionの検証違反を指し、「対象なし」と分けて記載する。

### 2.3 表示と例外の共通事項

- 一覧は全件を追加した順の逆順に表示し、完了タスクも含める。編集・完了切替で追加順を変えない。
- 同じタイトルのタスクも別IDで登録できる。
- タイトル・説明は文字列として表示し、入力されたHTMLやスクリプトを実行しない。
- 対象が存在しない場合はデータを変更せず、`/todos` へリダイレクトしてMSG-011「タスクが見つかりません。」を表示する。
- データの取得失敗を対象なし・0件として扱わない。データの読み書き失敗は機能仕様書の例外フローに従う。
- 一覧への移動後に一覧取得が失敗した場合は、GET `/todos` の取得失敗処理に従う。
- 削除確認専用画面、共通エラー専用画面、自動再試行は追加しない。

## 4. エンドポイント詳細

### 4.1 GET /todos

| 項目 | 内容 |
| --- | --- |
| 目的 | 登録済みの全タスクを一覧表示する |
| リクエスト | GET `/todos`。URL内のID、検索条件、送信フォーム項目はなし |
| 正常時の処理 | 全タスクを取得し、追加順の逆順でSCR-001を表示する。タイトル、完了状態、詳細リンク、完了切替ボタンを表示する。0件ならMSG-009と「タスクを追加」を表示する |
| 入力エラー時の処理 | 対象となる入力項目がないため該当なし |
| 対象が存在しない場合の処理 | 個別タスクを指定しないため該当なし。全件取得の結果が0件の場合は正常として扱う |
| データ取得失敗時の処理 | SCR-001内にMSG-012を表示する。0件の案内は表示せず、再読み込みによる再試行を案内する |
| 対応するControllerメソッド | `list()` |

一覧のタイトルからGET `/todos/{id}`、「タスクを追加」からGET `/todos/new` へ進む。完了切替ボタンはPOST `/todos/{id}/toggle` を送信する。

### 4.2 GET /todos/new

| 項目 | 内容 |
| --- | --- |
| 目的 | 新規タスクの登録フォームを表示する |
| リクエスト | GET `/todos/new`。URL内のID、送信フォーム項目はなし |
| 正常時の処理 | title・descriptionが空のSCR-002を表示する。必須・任意と上限文字数、「登録する」「キャンセル」を表示する。タスクは保存しない |
| 入力エラー時の処理 | 初期表示では入力を受け付けないため該当なし。登録時の検証はPOST `/todos` で行う |
| 対象が存在しない場合の処理 | 既存タスクを参照しないため該当なし |
| 対応するControllerメソッド | `showCreateForm()` |

「登録する」はPOST `/todos` を送信する。「キャンセル」は保存せずGET `/todos` へ移動する。

### 4.3 POST /todos

| 項目 | 内容 |
| --- | --- |
| 目的 | 入力したタイトルと説明から新規タスクを作成する |
| リクエスト | POST `/todos`。フォーム項目はtitle（必須）・description（任意）。IDと完了状態は入力させない |
| 正常時の処理 | titleの前後の空白を除去し、title・descriptionを検証する。一意のIDを付け、未完了として保存する。`/todos` へリダイレクトし、一覧の先頭に登録結果とMSG-001を表示する。同名タスクがあっても登録する |
| 入力エラー時の処理 | 保存せずSCR-002を再表示する。入力内容を保持し、違反項目にMSG-006～008の該当メッセージを表示する。修正後は同じPOST `/todos` で再送信する |
| 対象が存在しない場合の処理 | 新規作成のため該当なし |
| 保存失敗時の処理 | SCR-002に入力内容を保持してMSG-013を表示し、再操作を案内する。成功メッセージは表示しない |
| 対応するControllerメソッド | `create()` |

説明が未入力でも登録でき、後から詳細を開いた際は「説明なし」と表示する。

### 4.4 GET /todos/{id}

| 項目 | 内容 |
| --- | --- |
| 目的 | 指定したタスクの詳細を表示する |
| リクエスト | GET `/todos/{id}`。URL内に対象IDを指定する。送信フォーム項目はなし |
| 正常時の処理 | IDでタスクを取得し、SCR-003にタイトル・説明・完了状態を表示する。説明なしの場合はMSG-010を表示する |
| 入力エラー時の処理 | title・descriptionの入力を受け付けないため、その入力検証は行わない |
| 対象が存在しない場合の処理 | `/todos` へリダイレクトし、MSG-011を表示する |
| データ取得失敗時の処理 | SCR-003内にMSG-012と「一覧へ戻る」を表示する。タスク内容と編集・削除ボタンは表示しない |
| 対応するControllerメソッド | `show()` |

「編集」はGET `/todos/{id}/edit`、「一覧へ戻る」はGET `/todos` へ進む。「削除」は詳細画面上の確認後にPOST `/todos/{id}/delete` を送信する。

### 4.5 GET /todos/{id}/edit

| 項目 | 内容 |
| --- | --- |
| 目的 | 指定したタスクの編集フォームを表示する |
| リクエスト | GET `/todos/{id}/edit`。URL内に対象IDを指定する。送信フォーム項目はなし |
| 正常時の処理 | 対象タスクを取得し、保存済みのtitle・descriptionを入力欄に設定してSCR-004を表示する。この表示では更新しない |
| 入力エラー時の処理 | 初期表示ではtitle・descriptionの入力を受け付けないため該当なし。編集内容の検証はPOST `/todos/{id}` で行う |
| 対象が存在しない場合の処理 | `/todos` へリダイレクトし、MSG-011を表示する |
| データ取得失敗時の処理 | SCR-004内にMSG-012と「一覧へ戻る」を表示する。入力フォームは表示しない |
| 対応するControllerメソッド | `showEditForm()` |

「保存する」はPOST `/todos/{id}` を送信する。「キャンセル」は変更を保存せずGET `/todos/{id}` へ移動する。

### 4.6 POST /todos/{id}

| 項目 | 内容 |
| --- | --- |
| 目的 | 指定したタスクのタイトルと説明を更新する |
| リクエスト | POST `/todos/{id}`。URL内に対象IDを指定し、フォームでtitle（必須）・description（任意）を送信する |
| 正常時の処理 | titleの前後の空白を除去し、title・descriptionを検証する。対象タスクを取得し、タイトル・説明だけを更新する。ID・完了状態・追加順は維持する。`/todos/{id}` へリダイレクトし、詳細に更新内容とMSG-002を表示する |
| 入力エラー時の処理 | 更新せずSCR-004を再表示する。入力内容を保持し、違反項目にMSG-006～008の該当メッセージを表示する。修正後は同じPOST `/todos/{id}` で再送信する |
| 対象が存在しない場合の処理 | 対象の取得・更新時に存在しないことが分かった場合は更新せず、`/todos` へリダイレクトしてMSG-011を表示する。新規作成として扱わない |
| データ取得・保存失敗時の処理 | 対象なしとは区別し、SCR-004に送信した入力内容を保持してMSG-013を表示する。再操作を案内し、成功メッセージは表示しない |
| 対応するControllerメソッド | `update()` |

説明を空にして保存した場合は、詳細でMSG-010「説明なし」を表示する。

### 4.7 POST /todos/{id}/delete

| 項目 | 内容 |
| --- | --- |
| 目的 | 利用者が削除を確認した対象タスクを削除する |
| リクエスト | POST `/todos/{id}/delete`。URL内に対象IDを指定する。業務上の送信フォーム項目はなし |
| 正常時の処理 | 対象タスクの存在を確認し、その1件だけを削除する。`/todos` へリダイレクトしてMSG-003を表示する。削除後に0件ならMSG-009も表示する |
| 入力エラー時の処理 | title・descriptionなどの入力項目がないため、その入力検証は行わない |
| 対象が存在しない場合の処理 | `/todos` へリダイレクトし、MSG-011を表示する。削除成功とは表示しない |
| データ取得・削除失敗時の処理 | `/todos` へリダイレクトし、MSG-014を表示する。利用者は一覧から対象の詳細を開いて再操作する |
| 対応するControllerメソッド | `delete()` |

削除前にSCR-003のブラウザ標準の確認ダイアログでMSG-016「このタスクを削除しますか？」を表示する。「OK」の場合だけPOSTを送信し、「キャンセル」では送信せず詳細画面にとどまる。削除確認用のGETや専用画面は設けない。

### 4.8 POST /todos/{id}/toggle

| 項目 | 内容 |
| --- | --- |
| 目的 | 指定したタスクの完了／未完了を切り替える |
| リクエスト | POST `/todos/{id}/toggle`。一覧の完了切替ボタンからURL内の対象IDを指定する。業務上の送信フォーム項目はなし |
| 正常時の処理 | 対象タスクを取得し、未完了なら完了、完了なら未完了に切り替えて保存する。タイトル・説明・追加順は変えない。`/todos` へリダイレクトし、完了への切替はMSG-004、未完了への切替はMSG-005を表示する |
| 入力エラー時の処理 | title・descriptionや変更先の状態を入力しないため、それらの入力検証は行わない |
| 対象が存在しない場合の処理 | `/todos` へリダイレクトし、MSG-011を表示する |
| データ取得・保存失敗時の処理 | `/todos` へリダイレクトし、MSG-015を表示する。成功メッセージは表示せず、一覧で再操作を案内する |
| 対応するControllerメソッド | `toggleComplete()` |

成功後の一覧では保存した状態を表示し、ボタンを「完了にする」または「未完了に戻す」に切り替える。確認ダイアログは設けない。

## 5. 画面と処理結果の対応

フォームを再表示する場合はPOSTの応答として同じ画面を表示するため、画面の初期表示URLへ移動する必要はない。例えば更新の入力エラーはPOST `/todos/{id}` の応答でSCR-004を表示する。

| 操作 | 正常時の表示・移動先 | 入力エラー時 | 対象なしの場合 |
| --- | --- | --- | --- |
| 一覧表示 | SCR-001（`/todos`） | 該当なし | 0件は正常表示 |
| 登録フォーム | SCR-002（`/todos/new`） | 該当なし | 該当なし |
| 新規作成 | `/todos` へリダイレクト | SCR-002を入力保持して再表示 | 該当なし |
| 詳細表示 | SCR-003（`/todos/{id}`） | フォーム入力なし | `/todos` へリダイレクト、MSG-011 |
| 編集フォーム | SCR-004（`/todos/{id}/edit`） | フォーム入力なし | `/todos` へリダイレクト、MSG-011 |
| 更新 | `/todos/{id}` へリダイレクト | SCR-004を入力保持して再表示 | `/todos` へリダイレクト、MSG-011 |
| 削除 | `/todos` へリダイレクト | フォーム入力なし | `/todos` へリダイレクト、MSG-011 |
| 完了切替 | `/todos` へリダイレクト | フォーム入力なし | `/todos` へリダイレクト、MSG-011 |
