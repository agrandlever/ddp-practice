## 1. 機能概要

### 1.1 本書の範囲

DDP07のTodoアプリ演習で実装する、タスク追加・一覧・詳細・編集・削除・完了切替の6機能を定義する。本人がWindows PCのブラウザから利用し、画面は一覧・登録・詳細・編集の4画面とする。

本書はrequirements-todo.md バージョン1.2を上位の基準文書とし、その機能要件を画面と操作の流れに具体化する。対象はタスクのCRUD（作成・読取・更新・削除）と完了／未完了の切り替えとする。ユーザー認証、複数ユーザー対応、カテゴリ・タグ機能は対象外とする。

タイトルは必須・100文字以内、説明は任意・500文字以内とする。H2のインメモリ方式（メモリ内に保存する方式）を使用し、起動中の再読み込みではデータを保持する。アプリ終了時には実行中の追加・編集・削除・完了切替の結果は失われ、次回起動時は6章の初期データ3件を再投入して開始する。初回起動時も同じ3件とする。削除確認とエラー表示は既存の画面内で行う。その他の制約と受け入れ基準は要件定義書5章・6章に従う。

### 1.2 関連ドキュメント

- 要件定義書: [requirements-todo.md](requirements-todo.md)（1.2、上位の基準文書）。
- 機能仕様書テンプレート: [functional-spec-template.md](functional-spec-template.md)。
- API設計書: 本書では作成しない。APIはプログラム間の通信窓口を指す。本演習はThymeleafによる画面操作を対象とする。
- DB設計書: 本書では作成しない。DBはデータベースを指す。タスクの基本情報は6章に示す。

| 用途 | 技術 |

## 3. ユースケース詳細

正常系は通常の成功手順、代替フローは入力修正やキャンセルなどの分岐、例外フローは対象なし・データの読み書き失敗への対応とする。共通の事前条件はアプリが起動していること。メッセージの文言は8章で定義する。

### UC-001: タスクを追加する

| 項目 | 内容 |
| --- | --- |
| 対応機能要件 | FR-001 |
| アクター | 個人ユーザー |
| 事前条件 | タスク一覧を表示している |
| 事後条件 | 新しいタスクが未完了で保存され、一覧に表示される |
| 正常系 | 下記参照 |

**正常系フロー:**
1. 利用者が一覧の「タスクを追加」を選択する。
2. システムが空のタスク登録画面を表示する。
3. 利用者がタイトルと任意の説明を入力し、「登録する」を選択する。
4. システムが入力値を7章のルールで検証する。
5. システムが一意のIDを付け、未完了のタスクとして保存する。
6. システムが一覧へ移動し、登録したタスクとMSG-001を表示する。

**代替フロー:**
- A1（手順3）説明を入力しない場合: 説明なしで手順4以降を実行する。
- A2（手順3）「キャンセル」を選択した場合: 保存せず一覧へ戻る。
- A3（手順4）入力が不正な場合: 登録画面に入力内容を保持し、該当項目にMSG-006～008の対応するエラーを表示する。修正後、手順3から再実行する。

**例外フロー:**
- E1（手順5）保存に失敗した場合: 登録画面に入力内容を保持し、MSG-013を表示する。成功メッセージは出さず、利用者が再度「登録する」を選択できるようにする。

### UC-002: タスク一覧を確認する

| 項目 | 内容 |
| --- | --- |
| 対応機能要件 | FR-002 |
| アクター | 個人ユーザー |
| 事前条件 | ブラウザでアプリにアクセスできる |
| 事後条件 | 全タスクのタイトルと完了状態、または0件の案内を確認できる |
| 正常系 | 下記参照 |

**正常系フロー:**
1. 利用者が `/todos` を開く。
2. システムが全タスクを取得する。
3. システムが追加した順の逆順で、タイトルと完了状態を表示する。完了済みのタスクも表示する。
4. 利用者が一覧を確認する。

**代替フロー:**
- A1（手順2）0件の場合: 一覧にMSG-009と「タスクを追加」を表示する。
- A2（手順4）タイトルを選択した場合: UC-003へ進む。「タスクを追加」はUC-001、完了切替はUC-006へ進む。

**例外フロー:**
- E1（手順2）取得に失敗した場合: 一覧画面内にMSG-012を表示する。取得失敗を0件として案内せず、利用者が再読み込みして再試行できるようにする。

### UC-003: タスク詳細を確認する

| 項目 | 内容 |
| --- | --- |
| 対応機能要件 | FR-003 |
| アクター | 個人ユーザー |
| 事前条件 | 一覧に対象タスクが表示されている |
| 事後条件 | 選択したタスクのタイトル・説明・完了状態を確認できる |
| 正常系 | 下記参照 |

**正常系フロー:**
1. 利用者が一覧のタスクタイトルを選択する。
2. システムがIDで対象タスクを取得する。
3. システムが詳細画面にタイトル・説明・完了状態を表示する。

**代替フロー:**
- A1（手順3）説明がない場合: 説明欄にMSG-010を表示する。
- A2（手順3）「一覧へ戻る」を選択した場合: 一覧へ戻る。「編集」はUC-004、「削除」はUC-005へ進む。

**例外フロー:**
- E1（手順2）対象が存在しない場合: 一覧へ戻し、MSG-011を表示する。
- E2（手順2）取得に失敗した場合: 詳細画面内にMSG-012と「一覧へ戻る」を表示する。タスク内容と編集・削除ボタンは表示しない。

### UC-004: タスクを編集する

| 項目 | 内容 |
| --- | --- |
| 対応機能要件 | FR-004 |
| アクター | 個人ユーザー |
| 事前条件 | 対象タスクの詳細を表示している |
| 事後条件 | タイトルと説明が更新され、詳細と一覧に反映される。完了状態は変更しない |
| 正常系 | 下記参照 |

**正常系フロー:**
1. 利用者が詳細の「編集」を選択する。
2. システムが保存済みのタイトル・説明を入力欄に設定して編集画面を表示する。
3. 利用者が内容を変更し、「保存する」を選択する。
4. システムが入力値を7章のルールで検証する。
5. システムが対象のタイトルと説明を更新する。
6. システムが対象の詳細へ移動し、更新内容とMSG-002を表示する。

**代替フロー:**
- A1（手順3）「キャンセル」を選択した場合: 変更を保存せず詳細へ戻る。
- A2（手順4）入力が不正な場合: 編集画面に入力内容を保持し、該当項目にMSG-006～008の対応するエラーを表示する。修正後、手順3から再実行する。
- A3（手順3）説明を空にした場合: 説明なしとして保存し、詳細にMSG-010を表示する。

**例外フロー:**
- E1（手順2・5）対象が存在しない場合: 更新せず一覧へ戻し、MSG-011を表示する。
- E2（手順2）取得に失敗した場合: 編集画面内にMSG-012と「一覧へ戻る」を表示する。入力フォームは表示しない。
- E3（手順5）更新に失敗した場合: 編集画面に入力内容を保持してMSG-013を表示する。成功メッセージは出さず、利用者が再度「保存する」を選択できるようにする。

### UC-005: タスクを削除する

| 項目 | 内容 |
| --- | --- |
| 対応機能要件 | FR-005 |
| アクター | 個人ユーザー |
| 事前条件 | 対象タスクの詳細を表示している |
| 事後条件 | 確認を確定すると対象1件が削除される。キャンセルすると削除されない |
| 正常系 | 下記参照 |

**正常系フロー:**
1. 利用者が詳細の「削除」を選択する。
2. ブラウザ標準の確認ダイアログ（その場で確認する小さな表示）にMSG-016を表示する。
3. 利用者が「OK」を選択する。
4. システムが対象タスクを削除する。
5. システムが一覧へ移動し、MSG-003を表示する。

**代替フロー:**
- A1（手順3）「キャンセル」を選択した場合: 削除要求を送信せず、詳細画面にとどまる。
- A2（手順5）削除後に0件となった場合: MSG-003に加え、MSG-009と「タスクを追加」を表示する。

**例外フロー:**
- E1（手順4）対象が存在しない場合: 一覧へ戻し、MSG-011を表示する。削除成功とは表示しない。
- E2（手順4）削除に失敗した場合: 一覧へ戻し、MSG-014を表示する。利用者は対象の詳細を開き、改めて削除できる。

確認ダイアログに専用の画面IDやURLは設けない。ボタン名はブラウザの表示言語に従う。

### UC-006: 完了状態を切り替える

| 項目 | 内容 |
| --- | --- |
| 対応機能要件 | FR-006 |
| アクター | 個人ユーザー |
| 事前条件 | 一覧に対象タスクが表示されている |
| 事後条件 | 対象の完了状態が切り替わり、一覧と詳細に反映される |
| 正常系 | 下記参照 |

**正常系フロー:**
1. 利用者が一覧で未完了タスクの「完了にする」を選択する。
2. システムが対象を取得し、完了に変更して保存する。
3. システムが一覧を表示し、対象の状態を「完了」、操作ボタンを「未完了に戻す」にしてMSG-004を表示する。

**代替フロー:**
- A1（手順1）完了タスクの「未完了に戻す」を選択した場合: 未完了に変更して保存する。一覧で「未完了」と「完了にする」を表示し、MSG-005を表示する。

**例外フロー:**
- E1（手順2）対象が存在しない場合: 一覧にMSG-011を表示する。
- E2（手順2）取得または保存に失敗した場合: 一覧にMSG-015を表示する。成功メッセージは出さず、利用者が再操作できるようにする。

各ユースケースで一覧へ戻った際のデータ取得に失敗した場合は、UC-002の例外フローに従う。エラー表示のための専用画面や自動再試行は設けない。

## 4. 画面一覧

URLの `{id}` は対象タスクのIDを表す。

| 画面ID | 画面名 | URL | 概要 |
| --- | --- | --- | --- |
| SCR-001 | タスク一覧 | `/todos` | 全タスクのタイトル（詳細へのリンク）・完了状態・完了切替ボタン、「タスクを追加」、操作結果や0件の案内 |
| SCR-002 | タスク登録 | `/todos/new` | タイトルの入力欄、説明の入力欄、「登録する」「キャンセル」、入力エラー |
| SCR-003 | タスク詳細 | `/todos/{id}` | タイトル・説明・完了状態、「編集」「削除」「一覧へ戻る」 |
| SCR-004 | タスク編集 | `/todos/{id}/edit` | 保存済みのタイトル・説明を表示する入力欄、「保存する」「キャンセル」、入力エラー |

タイトルは1行の入力欄、説明は複数行の入力欄とする。画面には日本語の項目名と必須・任意、上限文字数を表示する。Bootstrap 5で配置を整え、長い文章は折り返す。成功・処理エラーは既存画面の上部、入力エラーは該当項目の近くに表示する。

## 5. 画面遷移

```text
SCR-001 一覧 --[タスクを追加]--> SCR-002 登録
SCR-002 登録 --[登録成功／キャンセル]--> SCR-001 一覧
SCR-002 登録 --[入力エラー／保存失敗]--> SCR-002 登録（入力保持）
SCR-001 一覧 --[タスクタイトル]--> SCR-003 詳細
SCR-003 詳細 --[一覧へ戻る]--> SCR-001 一覧
SCR-003 詳細 --[編集]--> SCR-004 編集
SCR-004 編集 --[保存成功／キャンセル]--> SCR-003 詳細
SCR-004 編集 --[入力エラー／保存失敗]--> SCR-004 編集（入力保持）
SCR-003 詳細 --[削除→確認OK→削除成功]--> SCR-001 一覧
SCR-003 詳細 --[削除→確認キャンセル]--> SCR-003 詳細（変更なし）
SCR-003 詳細 --[削除失敗]--> SCR-001 一覧（エラー表示）
SCR-001 一覧 --[完了にする／未完了に戻す]--> SCR-001 一覧（結果表示）
詳細・編集・削除・完了切替 --[対象なし]--> SCR-001 一覧（エラー表示）
```

データの取得失敗は、そのデータを表示する既存画面内で案内する。削除の確認表示中は詳細画面にとどまる。

## 6. ビジネスルール

ビジネスルールは、タスク管理で共通して守る動作上の決まりを指す。

| ルールID | ルール名 | 説明 | 適用画面 |
| --- | --- | --- | --- |
| BR-001 | タスクの基本情報 | 一意のID、title（タイトル）、description（説明）、完了状態を持つ。同名タスクも別のタスクとして登録できる | 全画面 |
| BR-002 | 新規タスクの状態 | 登録直後は必ず未完了とする | SCR-002 |
| BR-003 | 一覧の順序と範囲 | 新しく追加した順で全件表示する。完了タスクも含め、ページ分割はしない。編集・完了切替で追加順を変えない | SCR-001 |
| BR-004 | 空の表示 | タスク0件は「タスクはありません」と登録への案内、説明なしは「説明なし」を表示する | SCR-001・003 |
| BR-005 | 編集範囲 | タイトルと説明だけを編集し、IDと完了状態は変えない | SCR-004 |
| BR-006 | キャンセル | 登録・編集の入力は保存しない。削除確認のキャンセルでは削除しない | SCR-002・003・004 |
| BR-007 | 削除 | 確認でOKを選択した対象1件だけを削除する | SCR-003 |
| BR-008 | 完了切替 | 一覧から未完了と完了を相互に切り替える。タイトルと説明は変えない | SCR-001 |
| BR-009 | 保存と結果 | 保存成功後に日本語で成功を知らせる。失敗時は成功と表示しない。結果表示後の再読み込みで登録・変更を再送信しないよう、成功後は表示先へ移動する | 全画面 |
| BR-010 | 演習中の保存期間 | H2インメモリに保存し、起動中は再読み込みしても内容を保持する。終了時に実行中の追加・編集・削除・完了切替の結果は失われ、次回起動時は初期データ3件を再投入して開始する | 全画面 |
| BR-011 | 表示と変更 | ページを表示するだけではデータを変更しない。タイトル・説明は文字列として表示し、入力されたHTMLやスクリプトを実行しない | 全画面 |

### 6.1 起動時の初期データ

要件定義書1.2の3.1に従い、初回起動時および再起動時は次の3件から開始する。

| タイトル | 説明 | 完了状態 |
| --- | --- | --- |
| Spring Bootを学ぶ | 公式ドキュメントを読む | 未完了 |
| 買い物に行く | 牛乳とパン | 未完了 |
| 部屋の掃除 | 説明なし（DBにはNULLを保存） | 完了 |

NULLは値がない状態を表す。初期データの投入は起動時に行い、画面の再読み込みでは行わない。通常の登録操作ではBR-002に従い未完了で作成する。全タスクを削除した場合の0件表示は引き続きBR-004に従う。

## 7. バリデーションルール

バリデーションは入力値の検証を指す。登録・編集に同じルールを適用し、サーバー側でも検証する。文字数の確認には標準の検証機能を用い、独自の文字数計算は追加しない。

| 項目名 | ルール | エラーメッセージ |
| --- | --- | --- |
| title（タイトル） | 必須。要件定義書に従い前後の空白を除去し、未入力・空白のみを拒否する | MSG-006: タイトルは必須です |
| title（タイトル） | 前後の空白除去後、100文字以内 | MSG-007: タイトルは100文字以内で入力してください |
| description（説明） | 任意。500文字以内 | MSG-008: 説明は500文字以内で入力してください |

入力エラー時は保存せず、入力内容を同じ画面に保持して修正できるようにする。説明の未入力は許可する。

確認の境界値は、タイトル1文字・100文字が正常、空欄・空白のみ・101文字がエラー、説明0文字・500文字が正常、501文字がエラーとする。

## 9. 状態遷移（該当する場合）

完了状態は「未完了」「完了」の2種類とする。表中の「未登録」「削除済み」はタスクが存在しないことを表し、保存する完了状態ではない。

| 現在の状態 | イベント | 次の状態 | 条件 |
| --- | --- | --- | --- |
| 未登録 | タスク登録 | 未完了 | 入力が正しく、保存に成功した場合 |
| 未完了 | 完了にする | 完了 | 状態の保存に成功した場合 |
| 完了 | 未完了に戻す | 未完了 | 状態の保存に成功した場合 |
| 未完了／完了 | タイトル・説明を編集 | 変更前の完了状態 | 内容だけを更新する |
| 未完了／完了 | 削除を確認して確定 | 削除済み | 削除に成功した場合 |
| 未完了／完了 | 編集・削除をキャンセル | 変更前の状態 | 保存・削除を行わない |

入力エラーや保存失敗では、この操作による状態変更を行わない。アプリ終了時にはインメモリの全タスクが失われ、実行中の追加・編集・削除・完了切替の結果は引き継がない。次回起動時には6.1の初期データ3件を再投入し、未完了2件・完了1件から開始する。
