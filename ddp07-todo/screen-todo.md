## 2. 画面一覧と共通表示

テンプレートは、ThymeleafがHTML画面を生成するためのファイルを指す。以下のテンプレートパスは `src/main/resources/templates/` からの相対パスとする。URLの `{id}` は対象タスクのIDである。

| 画面ID | 画面名 | 表示URL（GET） | テンプレート |
| --- | --- | --- | --- |
| SCR-001 | タスク一覧 | `/todos` | `todos/list.html` |
| SCR-002 | タスク登録 | `/todos/new` | `todos/form.html` |
| SCR-003 | タスク詳細 | `/todos/{id}` | `todos/detail.html` |
| SCR-004 | タスク編集 | `/todos/{id}/edit` | `todos/form.html` |

SCR-002とSCR-004は同じ `todos/form.html` を共用し、登録・編集に応じて見出し、入力欄の初期値、送信先、ボタン名、キャンセル先を切り替える。

日本語の項目名、必須・任意、上限文字数を表示する。Bootstrap 5で配置し、長い文章は折り返す。成功・処理エラーは既存画面の上部、入力エラーは該当項目の近くに表示する。タイトル・説明は文字列として表示し、入力されたHTMLやスクリプトは実行しない。文字コードはUTF-8、確認ブラウザはWindows版Chrome最新版とする。

## 3. SCR-002 / SCR-004: タスクフォーム入力項目

HTMLの `name` は、フォーム送信時に値を識別する項目名である。バリデーションは入力値の検証を指す。

| 項目名 | HTML | name | 必須 | バリデーション |
| --- | --- | --- | --- | --- |
| タイトル | `input[text]` | `title` | はい | `@NotBlank`, `@Size(max=100)` |
| 説明 | `textarea` | `description` | いいえ | `@Size(max=500)` |

`input[text]` は1行の文字入力欄（`<input type="text">`）、`textarea` は複数行の文字入力欄を表す。`@NotBlank` は未入力・空白のみを拒否するJavaの検証指定、`@Size(max=...)` は文字列の最大長を検証する指定である。

### 3.1 入力値・保存項目の対応

| 入力項目 | Java型 | 保存先 | 登録画面の初期値 | 編集画面の初期値 | 保存時の扱い |
| --- | --- | --- | --- | --- | --- |
| title | `String`（文字列） | `todos.title` | 空欄 | 保存済みのタイトル | 前後の空白を除去して検証し、1～100文字を保存 |
| description | `String`（文字列） | `todos.description` | 空欄 | 保存済みの説明。NULLなら空欄 | 500文字以内。未入力・空文字はNULLに統一 |

NULLは値がない状態を表す。「説明なし」は詳細画面での表示文言であり、フォームの初期文字列や保存値にはしない。

ID・完了状態・作成日時・更新日時の入力欄は設けない。IDは対象URLで使用し、登録時はDBで採番する。通常登録では未完了、編集では元の完了状態を維持する。完了切替は一覧の専用操作で行う。日時の自動設定はDB設計書に従う。

### 3.2 共用フォームの登録・編集の違い

| 項目 | SCR-002: 登録 | SCR-004: 編集 |
| --- | --- | --- |
| 見出し | タスク登録 | タスク編集 |
| フォーム初期表示 | GET `/todos/new` | GET `/todos/{id}/edit` |
| 入力欄 | タイトル・説明とも空欄 | 対象の保存済みタイトル・説明 |
| 送信ボタン | 登録する | 保存する |
| 送信先 | POST `/todos` | POST `/todos/{id}` |
| 成功後 | `/todos` へ移動し、MSG-001を表示 | `/todos/{id}` へ移動し、MSG-002を表示 |
| キャンセル | 保存せずGET `/todos` へ移動 | 保存せずGET `/todos/{id}` へ移動 |
| 入力エラー・保存失敗 | 登録用のフォームを入力保持して再表示 | 編集用のフォームを入力保持して再表示 |

GETは画面表示、POSTは保存などの変更要求に用いる。登録・編集は `application/x-www-form-urlencoded`（項目名と値を組み合わせるフォーム形式）で `title` と `description` を送信する。登録・編集の切り替えに新しい業務入力項目は追加せず、サーバーが表示する画面に応じて送信先を決める。

成功後はリダイレクト（ブラウザを別URLへ移動させる応答）し、GETで結果画面を表示する。結果画面の再読み込みで保存要求を再送信しない。入力エラー時はリダイレクトせず、POSTの応答として `todos/form.html` を再表示する。編集時は対象ID・送信先・キャンセル先も維持する。

## 4. バリデーションメッセージ

教材指定の以下の文言を使用する。末尾に句点は付けない。登録・編集で同じ検証と表示を行う。

| フィールド | ルール | メッセージ | 対応ID |
| --- | --- | --- | --- |
| title | 未入力 | タイトルは必須です | MSG-006 |
| title | 101文字以上 | タイトルは100文字以内で入力してください | MSG-007 |
| description | 501文字以上 | 説明は500文字以内で入力してください | MSG-008 |

タイトルの空白のみも未入力と同じMSG-006とする。タイトルの文字数は前後の空白を除去した後に検証する。説明は任意であり、未入力はエラーにしない。サーバー側で必ず検証し、文字数の確認には標準の検証機能を用いる。

入力エラー時は保存せず、入力済みのタイトル・説明を同じフォームに保持して、各入力欄の近くに対応するメッセージを表示する。利用者は修正して同じ送信ボタンから再操作できる。

## 5. SCR-001: タスク一覧

| 表示・操作 | 内容・動作 |
| --- | --- |
| タスクタイトル | 各タスクのタイトルを表示。選択するとGET `/todos/{id}` へ移動 |
| 完了状態 | `completed = false` は「未完了」、`true` は「完了」と表示 |
| 完了切替ボタン | 未完了では「完了にする」、完了では「未完了に戻す」。POST `/todos/{id}/toggle` を送信 |
| タスクを追加 | GET `/todos/new` へ移動 |
| 操作結果 | 登録・削除・完了切替などの結果を画面上部に表示 |
| 0件の案内 | 「タスクはありません。「タスクを追加」から登録してください。」と追加操作を表示 |

全タスクを新しく追加した順で表示し、完了済みも含める。DB設計書のID降順に従い、編集・完了切替では順序を変えない。ページ分割はしない。

完了切替の確認ダイアログは設けず、対象はURLのIDだけで指定する。タイトル・説明・変更先の完了状態をフォーム項目として送信しない。切替成功後は一覧へ移動し、保存した状態とそれに対応するボタン名を表示する。

## 6. SCR-003: タスク詳細

| 表示・操作 | 内容・動作 |
| --- | --- |
| タイトル | 保存済みのタイトルを表示 |
| 説明 | 保存済みの説明を表示。説明がなければ「説明なし」を表示 |
| 完了状態 | 「未完了」または「完了」を表示 |
| 編集 | GET `/todos/{id}/edit` へ移動 |
| 削除 | ブラウザ標準の確認ダイアログで「このタスクを削除しますか？」と表示 |
| 一覧へ戻る | GET `/todos` へ移動 |

削除確認で「OK」を選択した場合だけPOST `/todos/{id}/delete` を送信する。「キャンセル」の場合は送信せず、詳細画面にとどまる。削除成功後は一覧へ移動し、MSG-003を表示する。削除で0件になった場合は0件の案内も表示する。削除確認の専用画面は設けない。

## 7. 対象なし・処理失敗の表示

以下のメッセージIDと文言は機能仕様書1.3の8章に従う。入力検証のメッセージは本書4章に従う。

| 状況 | 表示先・画面の扱い | メッセージ |
| --- | --- | --- |
| 一覧取得失敗 | 一覧内で案内。0件と扱わず、再読み込みで再試行 | MSG-012 |
| 詳細取得失敗 | 詳細内に案内と「一覧へ戻る」。タスク内容・編集・削除ボタンは非表示 | MSG-012 |
| 編集フォーム初期表示時の取得失敗 | 編集画面内に案内と「一覧へ戻る」。入力フォームは非表示 | MSG-012 |
| 登録時の保存失敗 | 登録フォームに入力内容を保持し、再操作を案内 | MSG-013 |
| 編集送信後の取得・保存失敗 | 編集フォームに送信した入力内容を保持し、再操作を案内 | MSG-013 |
| 削除の取得・削除失敗 | 一覧へ移動し、詳細を開いて再操作できるようにする | MSG-014 |
| 完了切替の取得・保存失敗 | 一覧へ移動し、再操作を案内 | MSG-015 |
| 詳細・編集・更新・削除・完了切替の対象なし | データを変更せず一覧へ移動 | MSG-011 |

成功メッセージは保存・削除の成功後にのみ表示する。対象なしと読み書き失敗は区別する。失敗のための専用画面や自動再試行は追加しない。一覧への移動後に取得が失敗した場合は、一覧取得失敗の扱いに従う。

## 8. 初期データと画面確認

H2はインメモリ方式（メモリ内に保存する方式）を使用する。起動中の再読み込みではデータを保持する。アプリ終了時には実行中の追加・編集・削除・完了切替の結果が失われ、次回起動時には次の3件を再投入して開始する。初回起動時も同じとする。

| 初期データ | 説明（詳細画面） | 完了状態 |
| --- | --- | --- |
| Spring Bootを学ぶ | 公式ドキュメントを読む | 未完了 |
| 買い物に行く | 牛乳とパン | 未完了 |
| 部屋の掃除 | 説明なし | 完了 |

一覧はDB設計書の投入順とID降順に従い、「部屋の掃除」「買い物に行く」「Spring Bootを学ぶ」の順に表示する。説明は詳細画面で確認する。登録フォームは初期データの文言を入れず空欄で開く。「部屋の掃除」を編集する場合、説明欄は空欄で開く。

初期データは画面の再読み込みで追加しない。全件削除後は0件の案内を表示し、アプリを再起動すると初期データ3件に戻る。

## 9. 実装後の確認項目

本書は設計書であり、以下は実装後の確認用とする。

- [ ] 4画面のURLとテンプレートが2章の対応になり、登録・編集で `todos/form.html` を共用する。
- [ ] 入力項目は `title`・`description` の2つで、登録・編集の初期値、送信先、キャンセル先が正しい。
- [ ] タイトル1文字・100文字、説明0文字・500文字は保存できる。タイトルの前後の空白は除去される。
- [ ] タイトル空欄・空白のみ・101文字、説明501文字は拒否され、教材指定の文言と入力内容が保持される。
- [ ] 登録は未完了、編集は元の完了状態を維持し、説明を空にすると詳細に「説明なし」と表示する。
- [ ] 一覧・詳細の表示、削除確認、完了切替、成功・対象なし・処理失敗の案内が各設計書に従う。
- [ ] 起動時に初期データ3件が表示され、全件削除後の0件表示、再読み込みでの保持、再起動時の初期データ再投入を確認できる。
