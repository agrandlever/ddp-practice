# 要件定義書: Todo学習アプリ

> 作成日: 2026-09-10
> 作成者: 学習者
> バージョン: 1.2

本書はDDP07のTodoアプリ演習における上位の基準文書とする。機能仕様書は本書に基づいて画面と操作の流れを定義する。

---

## 1. プロジェクト概要

### 1.1 背景・目的

日々のやることを整理し、作業の抜け漏れを減らすため、自分のタスクを管理できるTodoアプリを作る。日常生活や学習など、用途を限定せずタスクを管理する。

### 1.2 対象ユーザー

自分のみ。日常のタスクを管理する本人が利用する。

- ユーザー種別1: 個人ユーザー。日常生活や学習など、用途を限定せず自分のタスク全般を管理する本人。
- ユーザー種別2: 該当なし。利用者は自分のみとし、追加のユーザー種別は設けない。

### 1.3 スコープ

スコープ（実現する範囲）は、本人のPC上で起動し、ブラウザから利用するTodoアプリの基本操作とする。

#### 対象範囲

- タスクのCRUD（作成・読取・更新・削除）：追加・一覧表示・詳細表示・編集・削除。
- タスクの完了／未完了の切り替え。

#### 対象外

- ユーザー認証（ログイン機能）。
- 複数ユーザー対応。
- カテゴリ・タグ機能。

## 2. 機能要件

### 2.1 機能一覧

IDは各機能を識別する番号。優先度は実装を進める際の優先順位を示す。「高」を優先し、「中」のタスク編集も演習の完成対象に含める。

| ID | 機能名 | 説明 | 優先度 |
| --- | --- | --- | --- |
| FR-001 | タスク追加 | タイトルと説明を入力してタスクを新規作成する。説明は任意で、初期状態は未完了とする。 | 高 |
| FR-002 | タスク一覧 | 全タスクを一覧表示し、各タスクのタイトルと完了状態を確認できる。 | 高 |
| FR-003 | タスク詳細 | 選択したタスクのタイトル・説明・完了状態を表示する。 | 高 |
| FR-004 | タスク編集 | タイトル・説明を編集して保存する。キャンセルした場合は変更しない。 | 中 |
| FR-005 | タスク削除 | 確認後に対象タスクを削除する。キャンセルした場合は削除しない。 | 高 |
| FR-006 | 完了切替 | 一覧から完了／未完了を切り替える。 | 高 |

#### 入力・表示・保存の共通仕様

- title（タイトル）は必須。前後の空白を除去した後、1～100文字とし、未入力や空白のみは登録・更新できない。
- description（説明）は任意とし、500文字以内とする。説明がない場合、詳細画面には「説明なし」と表示する。
- 入力エラー時は理由を日本語で表示し、入力済みの内容を保持する。サーバー側でも入力値を検証する。
- タスクには内部で一意のIDを付ける。同じタイトルのタスクも別のタスクとして登録できる。
- 一覧は追加した順の逆順（新しいタスクが先頭）で表示し、完了したタスクも表示する。ページ分割はしない。編集・完了切替で追加順は変えない。
- タスクが0件の場合は「タスクはありません」と追加操作への案内を表示する。
- 保存操作後は結果を日本語で知らせる。保存に失敗した場合は成功と表示せず、再操作を案内する。
- 存在しないタスクへの操作は「タスクが見つかりません」と表示し、一覧へ戻れるようにする。
- 登録・編集・削除・完了切替は、ページを表示するだけの操作では実行しない。
- タイトルと説明は文字列として表示し、入力されたHTMLやスクリプトを実行しない。
- 保存期間は3.1のH2インメモリ方式に従う。

### 2.2 ユーザーストーリー

ユーザーストーリーは、利用者が何を、何のために行いたいかを表す。

#### US-001: やることを記録して確認する

- **誰が**: 個人ユーザーとして
- **何を**: やることをタイトルと任意の説明で登録し、一覧と詳細で確認したい
- **なぜ**: 日常生活や学習のタスクを忘れずに管理するため

#### US-002: タスクを整理して進捗を把握する

- **誰が**: 個人ユーザーとして
- **何を**: 内容の編集、不要なタスクの削除、完了／未完了の切り替えをしたい
- **なぜ**: タスクを最新の状態に保ち、残っている作業を把握するため

## 3. 非機能要件

非機能要件は、機能以外の保存方式や利用環境などの条件を表す。

### 3.1 データベース

H2 Databaseのインメモリ方式（メモリ内にデータを保存する方式）を使用する。アプリの起動中は保存済みのデータを画面の再読み込み後も利用できる。アプリ終了時には実行中の追加・編集・削除・完了切替の結果は失われる。初回起動時および次回起動時には、以下の初期データ3件を投入して開始する。

| タイトル | 説明 | 完了状態 |
| --- | --- | --- |
| Spring Bootを学ぶ | 公式ドキュメントを読む | 未完了 |
| 買い物に行く | 牛乳とパン | 未完了 |
| 部屋の掃除 | 説明なし（DBにはNULLを保存） | 完了 |

NULLは値がない状態を表す。初期データの再投入は起動時に行い、画面の再読み込みでは行わない。通常の画面操作で追加するタスクは未完了とする。全タスクを削除した場合は起動中に0件となり、従来どおり0件の案内を表示する。

### 3.2 対応ブラウザ

Windows版Chrome最新版を使用する。受け入れ確認時点の最新安定版で主要操作を確認する。

### 3.3 文字コード

文字コード（文字をデータとして表す方式）はUTF-8とする。ソースファイル、画面表示、フォームの送受信で日本語が文字化けしないようにする。

## 4. 技術スタック

技術スタックは、アプリを作るために組み合わせる技術を表す。

| レイヤー | 技術 |
| --- | --- |
| プログラミング言語 | Java 21 |
| バックエンド（サーバー処理） | Spring Boot 3.4系 |
| テンプレート（画面生成） | Thymeleaf |
| DB（データベース） | H2 Database（インメモリ） |
| ORM（データとJavaのオブジェクトを対応付ける仕組み） | Spring Data JPA |
| CSS（画面の見た目・配置） | Bootstrap 5 |
| ビルド（アプリの組み立て） | Gradle |

## 5. 制約事項

- WindowsとVS Codeを使用し、4章の技術構成で実装する。
- サーバー側で画面を生成する構成とし、本人がPCで起動・終了する。
- 演習に必要な基本操作と入力検証、対象なし・読み書き失敗の案内を扱う。高度なエラー処理は追加しない。
- Spring Security、CSRFを独立した要件とする仕様、H2ファイル永続化、再起動後のデータ保持、バックアップ・RTO、複数タブ競合制御、公開運用に関する追加要件は含めない。

## 6. 受け入れ基準

受け入れ基準は、実装が完成したと判断するための確認条件。チェック欄は実装後の確認用であり、本書作成時点では未実施とする。

### 6.1 共通基準

- [ ] 全CRUD操作（追加・一覧・詳細・編集・削除）が正しく動作する。
- [ ] 一覧・登録・詳細・編集の全画面が表示され、Chrome最新版で主要操作ができる。
- [ ] バリデーション（入力値の検証）が登録・編集の両方で正しく動作する。タイトルの空欄・空白のみ・101文字、説明の501文字は拒否され、日本語で理由が表示される。
- [ ] タイトル1文字・100文字、説明0文字・500文字は登録・更新できる。タイトルの前後の空白は除去される。
- [ ] 入力エラー時に入力内容が保持され、修正して保存できる。サーバー側でも入力値を検証する。
- [ ] 日本語のタイトル・説明を登録・編集し、一覧・詳細に文字化けせず表示できる。文字コードはUTF-8である。
- [ ] 登録・更新・削除・完了切替が対象以外のタスクに影響しない。
- [ ] アプリ起動中の再読み込みでは、保存済みの内容と完了状態が維持される。
- [ ] H2インメモリを使用し、初回起動時には3.1の初期データ3件（未完了2件・完了1件）が存在する。
- [ ] 実行中に追加・編集・削除・完了切替を行ってからアプリを終了・再起動すると、その操作結果は失われ、3.1のタイトル・説明・完了状態を持つ初期データ3件に戻る。
- [ ] 画面の再読み込みで初期データが重複投入されない。全タスクを削除した場合は0件の案内を表示し、再起動すると初期データ3件が再投入される。
- [ ] HTMLやスクリプト形式の入力は文字として表示され、実行されない。
- [ ] 保存成功時は日本語で結果が表示され、読み書き失敗時は成功と表示せず再操作が案内される。

### 6.2 機能別基準

- [ ] FR-001: タイトルのみ、またはタイトルと説明で追加できる。追加直後は未完了となり、一覧に反映される。同じタイトルでも別タスクとして登録できる。
- [ ] FR-002: 完了・未完了を含む全タスクのタイトルと完了状態が、新しく追加した順に表示される。0件の場合は空の状態と追加操作を案内する。
- [ ] FR-003: 一覧から選択したタスクのタイトル・説明・完了状態が正しく表示される。説明なしや存在しないタスクでも規定の案内が表示される。
- [ ] FR-004: タイトルと説明を変更して保存すると、一覧と詳細に反映される。完了状態は変更しない。キャンセルした場合は元の内容が維持される。
- [ ] FR-005: 削除確認を確定すると対象が一覧から消える。キャンセルした場合は残る。
- [ ] FR-006: 未完了から完了、完了から未完了の両方向に切り替えられ、一覧・詳細・起動中の再読み込み後の表示が一致する。

## 7. 用語集

| 用語 | 説明 |
| --- | --- |
| タスク（Todo） | 利用者が行う予定の作業。タイトル、任意の説明、完了状態を持つ。 |
| 完了状態 | 作業が終わっているかを表す状態。「未完了」または「完了」のいずれかで、相互に切り替えられる。 |
