# 画面設計書：オンラインじゃんけん

## 1. 基本情報

### 1.1 対象システム

オンラインじゃんけん

### 1.2 画面設計方針

- PC・スマートフォンの両方で利用できるレスポンシブ対応とする。
- 各画面の主要コンテンツは原則として画面中央へ配置する。
- 画面操作は必要最小限とし、対戦開始や結果画面への遷移など、自動化できる処理について不要な操作ボタンは設けない。
- 画面幅`768px`未満を狭い画面として扱い、対象要素を縦並びへ切り替える。
- 勝敗結果は文字サイズを大きくして強調するが、勝ち・負け・あいこによる色分けは行わない。

---

# 2. 画面一覧

| 画面ID | 画面名 | URL | Thymeleafテンプレート | 概要 |
|---|---|---|---|---|
| `SCR-001` | 初期・待機画面 | `/` | `index` | 対戦相手を待機する。2人揃うと自動的に対戦を開始する |
| `SCR-002` | 手の選択画面 | `/play` | `play` | グー・チョキ・パーから自分の手を選択する |
| `SCR-003` | 結果画面 | `/result` | `result` | 自分と相手の手、勝敗結果を表示する |
| `SCR-004` | 参加上限エラー画面 | `/` | `error/match-full` | 3人目のユーザーへ参加できないことを表示する |

# 3. SCR-001｜初期・待機画面

## 3.1 基本情報

| 項目 | 内容 |
|---|---|
| 画面ID | `SCR-001` |
| 画面名 | 初期・待機画面 |
| URL | `/` |
| HTTPメソッド | `GET` |
| テンプレート | `index` |
| 主な目的 | 対戦相手が参加するまで待機する |

## 3.2 通常時の表示項目

| No. | 項目 | 表示内容 | 備考 |
|---:|---|---|---|
| 1 | メインタイトル | `オンラインじゃんけん` | 常時表示 |
| 2 | 待機メッセージ | `対戦相手を待っています` | 待機中に表示 |

操作ボタンは設けない。

## 3.3 レイアウト

画面中央へ、タイトルと待機メッセージを縦方向に配置する。

```text
オンラインじゃんけん

対戦相手を待っています
```

## 3.4 対戦開始時

2人のユーザーが揃い、対戦開始可能になった場合は追加メッセージを表示せず、自動的に`SCR-002｜手の選択画面`へ遷移する。

状態確認は`GET /api/status`を2秒間隔で行い、`PLAYING`を受信した場合に`/play`へ遷移する。

## 3.5 対戦相手切断後

対戦中に相手の通信切断を検知した場合は、`SCR-001`へ戻し、次の順序で表示する。

```text
オンラインじゃんけん

対戦相手との通信が切断されました

対戦相手を待っています
```

切断メッセージ：

`対戦相手との通信が切断されました`

は一度だけ表示する。

ページを再読み込みした場合は、切断メッセージを再表示しない。

## 3.6 結果画面から戻った場合

`SCR-003`から先に初期画面へ戻り、もう一方のユーザーがまだ戻っていない場合も、通常の待機画面と同じ表示とする。

```text
オンラインじゃんけん

対戦相手を待っています
```

専用の待機メッセージは追加しない。

先に戻ったユーザーは結果確認済みとし、相手がまだ結果確認済みでない間、`GET /api/status`は`WAITING`を返す。表示は従来どおり`対戦相手を待っています`とする。

この待機中も現在の参加者として参加枠を保持し、10秒の参加枠解放の対象外とする。3人目は引き続き参加できない。

2人とも結果確認済みになった時点で、同じ2人で新しい対戦を自動的に開始し、`SCR-002`へ遷移する。

# 4. SCR-002｜手の選択画面

## 4.1 基本情報

| 項目 | 内容 |
|---|---|
| 画面ID | `SCR-002` |
| 画面名 | 手の選択画面 |
| URL | `/play` |
| 表示HTTPメソッド | `GET` |
| 手の送信HTTPメソッド | `POST` |
| テンプレート | `play` |
| 主な目的 | じゃんけんの手を選択・確定する |

## 4.2 初期表示

画面タイトル：

`じゃんけんの手を選んでください`

その下に3つの手を横並びのボタンとして表示する。

```text
じゃんけんの手を選んでください

[ グー ] [ チョキ ] [ パー ]
```

## 4.3 手の選択項目

| 表示名 | HTML要素 | 送信項目名 | 送信値 | 必須 |
|---|---|---|---|---|
| グー | `button` | `hand` | `rock` | はい |
| チョキ | `button` | `hand` | `scissors` | はい |
| パー | `button` | `hand` | `paper` | はい |

受け付ける値は`rock`、`scissors`、`paper`の3種類のみとする。

## 4.4 手を確定した後

自分の手を選択した後は、次の内容を表示する。

```text
じゃんけんの手を選んでください

[ グー ] [ チョキ ] [ パー ]

あなたの手：グー

対戦相手の選択を待っています
```

表示する手の名称は、内部値を次の日本語へ変換する。

| 内部値 | 表示 |
|---|---|
| `rock` | グー |
| `scissors` | チョキ |
| `paper` | パー |

選択後は、

- 3つのボタンをすべて表示したままにする。
- 3つのボタンをすべて操作不可にする。
- 自分が選択したボタンだけ見た目を強調する。
- 相手の手は表示しない。

一度確定した手は、その対戦中は変更できない。

## 4.5 相手の選択待ち

自分の手だけが確定している場合、

`対戦相手の選択を待っています`

を表示する。

`GET /api/status`を2秒間隔で呼び出し、双方の手が確定して`RESULT_READY`になった場合は、追加メッセージを表示せず自動的に`SCR-003｜結果画面`へ遷移する。

## 4.6 バリデーションエラー

不正な`hand`が送信された場合、手を確定せず同じ画面を再表示する。

表示メッセージ：

`グー・チョキ・パーのいずれかを選択してください。`

表示位置：

3つの選択ボタンの下。

表示方法：

赤字。

エラー表示中も3つの選択ボタンは操作可能とする。

```text
じゃんけんの手を選んでください

[ グー ] [ チョキ ] [ パー ]

グー・チョキ・パーのいずれかを選択してください。
```

## 4.7 直接アクセス

対戦開始前に`/play`へ直接アクセスした場合は、この画面を表示せず`/`へ戻す。

## 4.8 レスポンシブ対応

### 画面幅768px以上

3つのボタンを横並びにする。

```text
[ グー ] [ チョキ ] [ パー ]
```

### 画面幅768px未満

3つのボタンを縦並びにする。

```text
[ グー ]

[ チョキ ]

[ パー ]
```

# 5. SCR-003｜結果画面

## 5.1 基本情報

| 項目 | 内容 |
|---|---|
| 画面ID | `SCR-003` |
| 画面名 | 結果画面 |
| URL | `/result` |
| HTTPメソッド | `GET` |
| テンプレート | `result` |
| 主な目的 | 双方の手と対戦結果を確認する |

## 5.2 表示項目

| No. | 項目 | 表示内容 |
|---:|---|---|
| 1 | 画面タイトル | `対戦結果` |
| 2 | 自分の手 | `あなたの手：○○` |
| 3 | 相手の手 | `相手の手：○○` |
| 4 | 勝敗結果 | 勝ち・負け・あいこのメッセージ |
| 5 | 戻るボタン | `初期画面に戻る` |

## 5.3 レイアウト

画面全体は中央配置とする。

自分の手を左、相手の手を右に同じ段で配置する。

```text
対戦結果

あなたの手：グー        相手の手：チョキ

あなたの勝ちです

[ 初期画面に戻る ]
```

## 5.4 勝敗結果

| 結果 | 表示メッセージ |
|---|---|
| 勝ち | `あなたの勝ちです` |
| 負け | `あなたの負けです` |
| あいこ | `あいこです` |

結果メッセージは通常の本文より大きい文字サイズで強調する。

勝ち・負け・あいこによる色分けは行わない。

## 5.5 初期画面へ戻る操作

`初期画面に戻る`ボタンを押した場合、

`POST /result/return`

を実行し、正常時はその後`/`へ遷移する。

予期しない内部エラー（`INTERNAL_ERROR`）が発生した場合は、HTTP `500 Internal Server Error`で`SCR-003`（テンプレート：`result`）を表示し、`MSG-003「通信エラーが発生しました。ページを再読み込みしてください。」`を表示する。この場合はリダイレクトしない。詳細は9.1節に従う。

ユーザーがボタンを押すまでは結果画面に留まる。

## 5.6 直接アクセス

対戦結果が存在しない状態で`/result`へ直接アクセスした場合は、結果画面を表示せず`/`へ戻す。

## 5.7 通信監視

結果画面では`GET /api/status`によるポーリングを行わない。

そのため、結果画面表示中の対戦相手の通信切断は即時には検知しない。

## 5.8 レスポンシブ対応

### 画面幅768px以上

自分の手を左、相手の手を右に表示する。

```text
あなたの手：グー        相手の手：チョキ
```

### 画面幅768px未満

自分の手と相手の手を縦並びにする。

```text
あなたの手：グー

相手の手：チョキ
```

# 7. 画面遷移

## 7.1 基本フロー

```text
SCR-001 初期・待機画面
    ↓
2人のユーザーが揃う
    ↓ 自動遷移
SCR-002 手の選択画面
    ↓
双方の手が確定する
    ↓ 自動遷移
SCR-003 結果画面
    ↓
「初期画面に戻る」を押す
    ↓
SCR-001 初期・待機画面
```

2人とも結果確認を終了した場合は、既存仕様に従って新しい対戦を開始し、`SCR-002`へ遷移する。

## 7.2 3人目のアクセス

```text
GET /
    ↓
すでに2人が参加中
    ↓
SCR-004 参加上限エラー画面
```

## 7.3 対戦相手切断

```text
SCR-002 手の選択画面
    ↓
相手との通信を10秒以上確認できない
    ↓
SCR-001 初期・待機画面
    ↓
「対戦相手との通信が切断されました」を一度だけ表示
```

## 7.4 不正な手の送信

```text
SCR-002 手の選択画面
    ↓
不正なhandを送信
    ↓
SCR-002を再表示
    ↓
選択ボタン下にエラーメッセージを赤字で表示
```

## 9.1 予期しない内部エラー時のMSG-003表示

画面系エンドポイントで`INTERNAL_ERROR`が発生した場合は、HTTP `500 Internal Server Error`で、エラーが発生したリクエストに対応する現在の画面を表示する。その画面に`MSG-003「通信エラーが発生しました。ページを再読み込みしてください。」`を表示する。

| エラーが発生したリクエスト | 表示する画面 | テンプレート |
|---|---|---|
| `GET /` | `SCR-001` 初期・待機画面 | `index` |
| `GET /play` | `SCR-002` 手の選択画面 | `play` |
| `POST /play` | `SCR-002` 手の選択画面 | `play` |
| `GET /result` | `SCR-003` 結果画面 | `result` |
| `POST /result/return` | `SCR-003` 結果画面 | `result` |

新しい共通エラー画面やHTTPエンドポイントは追加せず、リダイレクトもしない。`POST /result/return`で内部エラーが発生した場合も、初期・待機画面へ遷移せず`SCR-003`を表示する。

`GET /api/status`の内部エラー応答は画面表示ではなく、API設計書6.3節に定義したHTTP `500 Internal Server Error`のJSONとする。

MSG-003の具体的な色や細かな表示位置は今回定義しない。また、新たな状態変更ルールは定義せず、機能仕様書のUC-003 E1にある対戦終了仕様は維持する。

# 12. 設計書間の整合性確認結果

切断時の表示先・遷移方法は、API設計書3.6節「相手の切断を検知した場合」および5.3節「切断検知後」へ反映済みである。

API設計書と本書では、次の動作に表現を統一した。

1. JavaScriptは`GET /api/status`の`OPPONENT_DISCONNECTED`を受信して対戦相手の切断を検知する。
2. 初期・待機画面`/`（`SCR-001`）へ遷移する。
3. `SCR-001`で`対戦相手との通信が切断されました`を一度だけ表示する。
4. あわせて、通常の待機メッセージ`対戦相手を待っています`を表示する。
5. ページを再読み込みした場合は、切断メッセージを再表示しない。

サーバー側では残ったユーザーを初期・待機状態とし、新しいユーザーを受け入れ可能にする。`GET /api/status`の`OPPONENT_DISCONNECTED`自体も1回だけ返し、その後は`WAITING`を返す。

以上により、切断時の表示先・遷移方法に関する設計書間の整合性確認は完了した。3.5節に定義した`SCR-001`の画面仕様自体に変更はない。
